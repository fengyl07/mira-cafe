# 雨夜咖啡馆

暴雨后的夜晚，用户推门进入一家即将打烊的咖啡馆，遇见 26 岁的旅行摄影师 Mira。她穿着琥珀色雨衣，戴着银色星星发夹，在等一个人，但不肯马上说原因。

页面以场景和角色为主体。用户可以打字，也可以按住说话。Mira 会出声、变表情、做动作，并在剧情节点触发门口的一段画面。

## 启动

需要 Python 3.10 及以上。Windows 上一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

脚本会创建 `.venv`、安装依赖，并打开 `http://127.0.0.1:8000`。

依赖已经装好时，也可以：

```powershell
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

测试：

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -t . -v
```

没有 API 密钥时默认是剧本演示，核心流程不用密钥也能走完。密钥放在本机 `.env`，不要提交。可参考 `.env.example`。

## 建议演示

用 Chrome 打开页面，手机宽度或桌面居中都可以。

1. 点「推门进去」，听开场白，看到待机之外的说话状态。
2. 输入「我来躲雨」。她会放松，咖啡馆灯光变暗。
3. 在她说话时按住「按住说话」。语音、字幕和未播完的动作会马上停，画面进入倾听。
4. 松手后如果浏览器能听写，就说「你在等谁」。不能听写就打字发送同一句。她会看手机，情绪变低落。
5. 再说「到底在等谁」。门口会出现一段由这句台词触发的光。
6. 打开「调试」，勾选「下一次门口画面失败」，再发「再看一次门口」，看到加载后的失败提示。
7. 点「模拟她没接上话」，看到超时后的恢复。

## 系统结构

- `app/main.py`：会话、回合、取消、听写入口，以及页面托管。
- `app/session.py`：每轮 `turnId`。更早的回合不能再提交状态。
- `app/director.py`：剧本和模型输出都收成同一份角色指令。
- `app/voice.py`：有密钥且未强制剧本时，调用兼容 OpenAI 的听写和语音合成。
- `web/`：移动端优先的场景页。桌面端是居中的同一画面。

一次回合的事件顺序是：倾听或发送、思考、说话。说话时带着字幕、表情、动作和可选的门口画面。

## 语音和打断

打断使用按住说话，而不是自动检测开口。按下的瞬间就能停掉她，不依赖回声消除，演示也更稳。选择原因是 72 小时里要保证「说话中被打断」每次都能成功。

按下时发生这些事：

1. 本地世代号加一，立刻停止正在播放的声音、字幕、闪电和门口画面。
2. 通知服务端取消当前 `turnId`。服务端中止这一轮的等待、模型请求和语音合成。
3. 页面进入倾听。浏览器支持时使用 Web Speech 听写；不支持时改录音并上传。
4. 新的回复使用更大的 `turnId`。服务端如果发现回合已经过期，或连接已经断开，就不再写入会话。
5. 页面收到旧世代的响应直接丢弃，不会重新开口或把画面播回去。

没有密钥时，听写优先走 Chrome 的 Web Speech，朗读走浏览器语音。国内网络下 Web Speech 可能失败，这时用文字继续；按下麦克风仍然会完成打断。配置了 `OPENAI_API_KEY` 且 `MOCK=0` 时，对话走模型，听写和合成走对应的音频接口。合成失败时退回浏览器朗读。

## 角色指令

模型或剧本只返回这份结构，页面不接受自由文本控制画面：

```json
{
  "say": "你听见门口那声了吗？不是他。",
  "emotion": "sad",
  "pose": "speak",
  "action": "check_phone",
  "scene": "rain",
  "fx": null,
  "media": {"type": "sequence", "id": "door_light"}
}
```

- 情绪至少三种：`wary` 警惕、`warm` 放松、`sad` 低落。
- 说话之外的动作至少两种：`hold_cup` 握杯、`check_phone` 看手机。
- 场景变化：躲雨后 `lights_dim` 灯光变暗；尚未建立信任时追问原因，会变成 `rain_heavier` 并打一次闪。
- 视觉事件：只有她已经提过自己在等人、用户再追问或提到门口时，才播放 `door_light`。画面内部的加载等待是这段素材自己的加载，不是全页定时器。

角色动画是分层矢量状态：待机呼吸、倾听前倾、思考看向一侧、说话时嘴部张合，另外带眨眼。门口那段是覆盖在门上的序列演出，处理了加载、播放结束、中途打断，以及调试开关里的加载失败。

## 模型、媒体和素材

- 对话：兼容 OpenAI 的 `chat/completions`。未配置密钥时用内置剧本。
- 听写：浏览器 Web Speech；服务端可选 `audio/transcriptions`。
- 朗读：浏览器 `speechSynthesis`；服务端可选 `audio/speech`，返回 mp3 后由页面播放。
- 画面：页面内原创矢量插画和 CSS 演出，没有外部图片或视频文件。
- 角色、剧情和视觉均为本题原创。

密钥不要写进仓库。`.env` 已被忽略。

## 取舍

- 后端用 FastAPI，页面由同一个进程托管，所以本地一条命令就能打开完整体验。
- 不做 Live2D 或实时生视频。矢量状态和一段剧情演出更稳，也足够看清情绪、动作和打断。
- 会话放在内存里。刷新页面就是新的一次进店，不做账号和长时存储。
- 模型输出先做 JSON 校验。校验失败会重试一次，再失败就保留当前情绪和场景，只说一句让用户重复。超时和断线会停在可恢复的待机，而不是假装她正常回答。

## 已知问题

- Chrome 的 Web Speech 在无法访问其语音服务时会失败。文字路径和打断仍然可用。
- 浏览器朗读在部分手机上可能没有中文音色，字幕仍会显示。
- 快速连按麦克风时，空识别会提示「没听清」，不会播放上一句。
- 剧本模式只会沿着 Mira 等人的这条短剧情走，不是开放闲聊。

## 投入时间

这次实现大约用了 3 小时。

## 如果再做两周

先补本地听写，避免依赖浏览器云端语音。然后做开口检测和「嗯」「对」这类附和的过滤，以及口型、流式字幕、会话回放。角色资源再收成配置，方便换成另一组表情和动作。
